# Arcade Skins for Manic EMU

Quick heads-up on the page layout and the 2.0.2 change:

- Using Manic EMU 2.0.2 or newer? Use the regular releases [v1.0 to v1.11](https://github.com/TheMameKing/manic-emu-arcade-skins/releases?page=2), the ones without “Legacy” in the name.
- Using Manic EMU 2.0.1 or earlier (for example a sideloaded copy)? Use the Legacy releases. They’re the old sets, unchanged.
- What changed: only the button numbering. Manic 2.0.2 changed the button inputs, so I patched every set to match. In the updated sets the buttons now read 1, 2, 3 on the top row and 4, 5, 6 below, left to right (right to left on the left-handed sets). The Legacy sets use the old numbering, which is laid out differently and can vary by game. Using the wrong set for your version gives scrambled inputs.
- Tekken-Rival Fix is retired. With the new numbering, the regular 4 Button works for Tekken and Rival Schools in my testing. The old Tekken-Rival Fix skins are still in the Legacy releases for 2.0.1.
- Twin Stick skins work on both versions. In my testing they play the same, and the Legacy copies are identical.
- iPad skins: All iPad sets work on both Manic EMU versions, with one exception: the iPad Street Fighter set uses a special button order and is only compatible with the Legacy mapping. iPad users should use the regular releases for all other layouts.
- The device matrix is complete — every planned layout and device combination is finished. Going forward I’ll mainly be, cleaning up my pages, fine-tuning existing skins where needed and working on dedicated **combo skins** (mapping 2–3 buttons to a single input so special attacks are easier on touchscreens) as well as **extra skins** like big buttons or any missing good ideas i can think of that haven't been tried. Feedback and combo requests are welcome — just open an issue and tell me the game + the button combinations you want.

## Installing from GitHub

1. Download the zips you want.
2. In the Files app, **press and hold** the zip, tap **Share**, then choose **Manic EMU**.
3. The **ZIP File Handling** screen appears. **Tap the zip so the red check mark is on**, then tap **Confirm**. The check mark is what unzips the skins. If you skip it, Manic imports the zip as a game instead of as skins.
4. In Manic EMU, assign the skin to your arcade games.

**Prefer to install single skins, or the share doesn't work?** Tap the zip in Files to unzip it, then use any of these:

* **One skin:** tap the `.manicskin` file. It opens in Manic EMU and imports right away, and a pop-up confirms "skin imported" and lists the skin.
* **Several skins:** press and hold a `.manicskin` file, choose **Select**, pick the ones you want, then tap **Share** and choose **Manic EMU**.
* **From inside Manic EMU:** tap **Assign Skin → New Skin → Open File** and pick the `.manicskin` files. Open File only accepts `.manicskin` files, not zips.

**Easier option:** Starter Packs of the same sets are on [DeltaStyles](https://deltastyles.com/user/3027-themameking), where you can install a pack in a few taps.

## Button mapping

Manic EMU's arcade core numbers the buttons like this:

| Skin input | Arcade button |
|---|---|
| `b` | Button 1 |
| `a` | Button 2 |
| `y` | Button 3 |
| `x` | Button 4 |
| `l1` | Button 5 |
| `r1` | Button 6 |

This table applies to every current set, iPhone and iPad.

In the current sets the buttons read 1, 2, 3 on the top row and 4, 5, 6 below, left to right (right to left on the left-handed sets). The Legacy sets number them differently; see [Old button numbering](#old-button-numbering).

A game that needs Buttons 1 to N needs every number from 1 to N present on the skin, which is why 1-Button uses `b` and 3-Button uses `a`, `b` and `y`.

**Twin Stick** has no center buttons. In Smash TV and Total Carnage, the right stick fires in 4 directions (the `x` / `y` / `a` / `b` inputs).

![Button order](images/button-mapping/button-order-v2.png)

Button roles vary by game. For example, in Golden Axe Button 1 is attack, Button 2 is jump and Button 3 is magic. If a button does something unexpected, check the game’s controller menu in Manic EMU, since the same button number can mean different things in different games.

## Game-specific notes

Things found while play-testing. Games can behave differently from what you'd expect, so these are worth knowing before you pick a skin. Most of these are limits of the emulator, not the skins.

### Racing
- **Steering feel:** In Pole Position (World) the D-Pad steers slower and steadier, while the Joystick turns faster and sharper. Try both. Needs more testing in other racing games.
- **Chase H.Q.:** Left stick steers, B is gas, A is brake, Y is turbo and X is shift. Use a 4-Button skin.
- **WEC Le Mans 24:** Left stick steers, B is gas, A is brake and Y is shift.
- **Hard Drivin':** Not playable on any skin with the manual shift setting, use automatic setting. The shifter and the steering both use the left stick, and you have to hold the shifter in gear to drive. With the D-Pad you stay locked in 2nd gear. Needs more testing in other racing games that don't use the toggle shift option like Chase H.Q. and WEC Le Mans 24 do.

### Known limits
- **Twin-stick games that also need buttons (Vindicators, Sarge, Lost Tomb):** The emulator ties the face buttons to the right stick, so every button press also moves the stick. There's no skin fix for this, which is why there are no twin-stick skins with buttons.

## For skin makers

Each `.manicskin` is a zip containing `info.json`, PNG art and PDF button images. The layout lives in `info.json` under `representations.iphone.edgeToEdge.{portrait, landscape}` (iPad skins use `representations.ipad.standard.{portrait, landscape}`):

- `assets.large`: PNG with a transparent hole where the game screen goes
- `items`: thumbsticks, D-pads and buttons. Each button has an `inputs` list, and a button can send several at once (for example `["a", "l1", "r1"]`)
- `mappingSize` and `screens[].outputFrame`: size and screen position
- `translucent`: `true` for Full Screen landscape, where buttons are drawn over the game
- D-pad items (D-Pad set) use an `inputs` object instead of a list: `{"up": "up", "down": "down", "left": "left", "right": "right"}`, with `asset.normal` pointing to the D-pad image (`dpad.pdf`)

There is also a [tools](tools) folder with a skin checker (`check_skin.py`), a contact-sheet drawing tool (`contact_sheet.py`) and format notes. They are MIT licensed and you can use them on your own collections.

## Pre-Release Verification

Every release including the Legacy ones goes through automated verification designed to catch structural, naming, positioning, and consistency issues before skins are published.

**Pre-Release Quality Assurance & Automated Verification:**

- **Colourway completeness:** Exactly 22 colourways required per layout, with no missing or unexpected extras.
- **Identifier validation:** Strict identifier formatting and common family-prefix checks across colourways.
- **Duplicate detection:** Prevents duplicate names or identifiers that could cause files to overwrite one another.
- **Handedness validation:** Ensures joystick/D-pad placement and action button positioning follow the intended handedness.
- **System control validation:** Checks required system controls and pill ordering (Start → FF, Load → Save).
- **Touch area collision detection:** Detects overlapping touch areas, with intentional button-to-button exceptions.
- **Canvas boundary checks:** Flags controls extending outside the canvas, allowing only a narrow tolerance for harmless overspill.
- **Tate aspect ratio enforcement:** Ensures Tate layouts maintain the required aspect ratio.
- **Layout configuration checks:** Verifies the correct number of joysticks, D-pads, and action buttons for each layout type.
- **Optional palette verification:** Compares measured background colours against reference palette values.
- **Cross-skin consistency:** Checks colourway slug consistency across layouts and prevents different layouts from sharing identifier families.
- Release ZIP integrity and corruption checks
- Internal .manicskin archive readability and metadata validation
- Required asset and control-file existence checks
- Image dimensions verified against mapping specifications
- Required system input completeness
- Dedicated D-pad and twin-stick configuration validation
- D-pad Only restrictions
- Legacy identifier compatibility protection
- Unexpected files and archive contents detection

Automated verification is followed by visual contact-sheet inspection and hands-on testing of representative layouts before release. There is a version of my scripts you can use in the tools section with my build specific checks in it taken out so it doesn't throw errors on your skins. You can also check .deltaskins with it by changing the extension of the .deltaskin to .manicskin since they are built on the same architecture then change it back.
